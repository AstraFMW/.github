# ◈ What is ASTRA?

**ASTRA is a proprietary, full-stack FiveM framework engineered from the ground up for the ASTRA ecosystem.**

Instead of assembling a server from dozens of disconnected resources, ASTRA provides a unified platform where first-party systems communicate through a shared `astra` interface.

The framework provides the foundation for:

<table>
<tr>
<td width="50%">

### ⚡ Core Infrastructure

- Unified `astra` interface
- Middleware pipeline
- Bidirectional callbacks
- Centralized player state
- Framework services
- Resource lifecycle management

</td>
<td width="50%">

### ◈ Gameplay Infrastructure

- Character lifecycle
- Native inventory
- Employment systems
- Vehicle ownership
- Civilian activities
- Public-safety systems

</td>
</tr>
</table>

Every first-party ASTRA resource is designed around the same architecture, conventions, and internal APIs.

> 🔒 **PRIVATE FRAMEWORK**
>
> ASTRA Framework and its first-party components are maintained exclusively for authorized ASTRA environments. Source code, internal resources, deployment tooling, and framework components are **not distributed for general public or unauthorized third-party use.**

# 🚀 Internal Deployment

<div align="center">

### CODE → BUILD → DEPLOY

`DEVELOPMENT` → `TESTING` → `STAGING` → `PRODUCTION`

</div>

<br/>

ASTRA environments are provisioned through an internally maintained deployment pipeline.

### `ASTRA-TxRecipe`

The internal txAdmin deployment system provides a standardized foundation for authorized ASTRA environments.

It handles the foundation required for:

- Framework deployment
- Resource provisioning
- Dependency management
- Environment configuration
- Development environments
- Testing environments
- Production deployments

Framework resources and supporting infrastructure remain within ASTRA-controlled repositories throughout the deployment lifecycle.

# 🔐 Access Control

<div align="center">

### AUTHORIZED PERSONNEL ONLY

</div>

ASTRA Framework is **not distributed as a general-purpose public FiveM framework.**

Access to framework source code, internal repositories, development resources, deployment tooling, releases, and documentation is restricted to authorized ASTRA developers and approved personnel.

Access to ASTRA infrastructure does **not** grant authorization to:

❌ Redistribute source code  
❌ Republish framework resources  
❌ Sublicense ASTRA software  
❌ Rebrand ASTRA components  
❌ Sell framework resources  
❌ Deploy components outside authorized environments  
❌ Provide repository access to unauthorized parties

Repository and framework access may be granted or revoked at the discretion of the ASTRA Framework team.

Applicable usage, modification, ownership, and distribution restrictions are defined by the private license included with each ASTRA Framework repository.
